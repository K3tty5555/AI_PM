飞书云文档格式是针对飞书文档生态优化的 Markdown 变体，支持飞书特有的语法和样式。

## 格式对照

### 1. 标题

标准 Markdown：
```markdown
# 一级标题
## 二级标题
```

飞书优化（保留标准语法，飞书会自动识别）：
```markdown
# 一级标题
## 二级标题
```

### 2. 表格

标准 Markdown：
```markdown
| 列1 | 列2 |
|-----|-----|
| 内容 | 内容 |
```

飞书优化（支持合并单元格）：
```markdown
| 列1 | 列2 |
|-----|-----|
| 内容 | 内容 |
| ^ | 合并上方单元格 |
```

### 3. 提及用户

飞书特有语法：
```markdown
@用户名
<at id="用户ID">@显示名</at>
```

### 4. 表情

飞书表情：
```markdown
:smile: :rocket: :warning:
```

### 5. 代码块

支持指定语言：
```markdown
```javascript
console.log('hello');
```
```

### 6. 引用

标准引用：
```markdown
> 这是引用内容
```

### 7. 列表

支持任务列表：
```markdown
- [ ] 未完成任务
- [x] 已完成任务
- 普通列表项
```

### 8. 分割线

```markdown
---
```

### 9. 高亮

飞书支持的高亮：
```markdown
==高亮文本==
```

### 10. 链接

```markdown
[链接文字](https://example.com)
```

## PRD 专用模板

> **🧭 模板选型（先定 doctype 再用本模板）**
>
> 本模板用于**全员评审 · 功能 PRD**（`doctype=full`，给研发落实现）。
> - **决策评审型**（拿方向 / go-no-go / 几方案选一，给决策层）→ 改用 `decision-review-template.md`，**不要**用本模板拼功能。
> - **Agent / Hybrid 产品** → 本模板 + `agent-supplement.md` 增量包（见下）。
> - **迭代 / 小补丁** → 仍走本完整模板，不塌成精简 bullet 版。
> - 选型机读字段（`doctype`）与完整规则见 `.claude/skills/ai-pm/phases/phase-5-prd.md` 步骤 A.0 / A.0.1。

> **Agent 增量包挂接说明**
>
> 本模板包含 3 个 `<!-- agent-supplement: AX -->` 标记，用于在生成 agent / hybrid 产品 PRD 时注入额外章节。
> - 标记本身是 HTML 注释，渲染后不可见，传统产品 PRD 完全无干扰
> - phase-5-prd.md 根据 `_memory/L1-decisions.md` 的 `product_type` 字段决定是否在标记位置展开 `agent-supplement.md` 对应章节
> - 详见 `templates/prd-styles/default/agent-supplement.md`

> ## ⚠️ PM 视角写作总指引（所有产品类型通用，强制阅读）
>
> 本模板是脚手架，**不是清单**。用 PM 视角填充，不是按工程师 / 设计师视角填充。具体判断方法见 `.claude/skills/ai-pm/references/pm-judgment-card.md`。
>
> **核心判断**（不分传统/Agent）：
> - 每段都问自己"**这是 PM 该决策的吗**？" 是 → 写；不是 → 移到附录"待 X 对齐"或交对应角色
> - **越界红线**：技术栈选型、接口字段名/路径/枚举值、数据库表、视觉毫秒/像素/色号、算法实现细节 → **不写**
> - **影响范围必表达**：每个改动列受影响的页面/接口/角色/已存量场景，研发依此定位代码（行内「同步影响：…」即可，不必独立成章）
> - **复用对照表**：**默认不写**，用「同 V1 / 复用一期逻辑」一句带过即可（制卡 V1.5–V1.8 实测都没有）；**仅"功能迁移 / 老系统接新引擎"类**才画「§4.x V1 复用对照表」（4 列），普通迭代画了全是废话（PITFALL-070）
> - **暂不纳入本期**：单列章节（反馈 / 原因 / 后续计划 3 列）—— 砍掉的需求要写清原因
> - **附录承接非 PM 内容**：能力矩阵 / 学科支持表 / 接口对接说明放附录 A/B，主体保持精炼
> - **修订日志 = V1.0 首评基线口径**：首评周期内的全部修改（含 PM-AI 协作打磨、落实评审决议的轮次）**熔进 V1.0 一行，不单列**；**+V1.x 的唯一条件 = 定稿之后这份文档又一次正式发给研发/评审的修订**（V3 定稿实证；单一事实源=判断卡 §八）
> - **字数预算（三档，单源=判断卡 §7.1）**：≤1 万字达标；超 1 万至 1.5 万须文件头 `<!-- over-budget-reason: 一句话超因 -->`；>1.5 万停、走台账外置或拆版本（拆版本须用户拍板）。字数以 `scripts/check-prd-word-count.py` 输出为准，动笔前先报预算（phase-5 A.0.3）
>
> 越界例子（PM 看到立即移除或重写）：
> - "用 Pinia / Vue3 / Redis" → 删，研发自决
> - `GET /api/questions?type=...` 字段名/枚举值 → 删，明示"由研发与引擎侧对齐后补充"
> - "动画 0.3s / 间距 16px / 字号 14 / #1D4ED8" → 删，明示"风格与 X 容器保持一致"或交设计
> - "V1.5 上线文件上传" 给用户的话术 → 改"暂时不支持 + 替代方案"

> **飞书友好写法规范（强制遵守）**
>
> PRD 最终目标是导入飞书云文档（直接 .md 上传 或 md2docx.py → docx 路径）。所有写法以飞书渲染效果为准，**不参考 IDE preview**。
>
> ✅ **该用**：
> - 表格 cell 内多条要点：`**标题**：内容<br>**标题2**：内容2` —— 加粗作为视觉锚点
> - 原型示意 cell 内图片：`![原型说明](../06-prototype/screenshots/xxx.png)<br>布局描述` —— 图片属于当前功能的「原型示意」右侧单元格（云文档 + 本地 DOCX 导出都支持）
> - 加粗：标准 `**xxx**`
> - 换行：标准 `<br>`（飞书 + md2docx.py 都支持）
> - 列表：标准 `- xxx` / `1. xxx`
>
> ❌ **不用**：
> - `<br/>` `<u>` `<sup>` 等 HTML 标签的非标准变体或装饰标签 —— 飞书会忽略当字面量
> - `▸` `·` `⭐` 等 Unicode 装饰符做 bullet —— 不同字体显示不一致，且对阅读无帮助
> - 表格 cell 内嵌 markdown 列表（`- xxx`）—— GFM 不支持表格 cell 内多行
>
> ⚠️ **超长 cell 的处理（5+ 条 bullet 或单条 > 100 字）**：
> - 拆出表格，用 `##### 小节标题 + 标准列表` 替代
> - 表格只留"短 cell"（单值或 ≤ 4 条短 bullet），保持紧凑
>
> 🟢 **云文档增强档（`output_profile=cloud_doc_enhanced` 时才用，普通 markdown 档绝不加）**：§二 的本期范围 / 关键约束、以及主要风险摘要，用 `> [!TIP] …`（范围 / 提示）/ `> [!WARNING] …`（风险 / 禁止）出**段落级高亮框**（不进表格 cell）；正文 / cell 用**语义调色板**：`<红>`=风险 / 禁止、`<灰>`=次要弱化、`==核心==`=本期 delta（黄底 ≤2）。**结构升级（渐进披露）**：文档顶部 `> [!INFO]` 状态头快照（版本 / 状态 / 负责人 / 优先级 / 档期，一次、≠修订日志）、实现细则 / 附录用 `<!-- fold -->` + 标题折叠、方案对比 / 原型并排用 `<!-- columns:N -->`…`<!-- col -->`…`<!-- /columns -->`、待对齐项升级三列（问题 / 负责人 / 截止）未决用 `<灰>`。**原型图归属**：渲染器声明 `table_cell_images=true` 时，详细功能设计里的原型图必须写进「原型示意」右侧 cell（`![](path)<br>描述`），不要写「见下图」后在表格外另放图片。完整规则见判断卡 §十。
