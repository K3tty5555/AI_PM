# 原型协作工作台

面向 PM 与评审者，在桌面浏览器中核对页面布局、逐页确认高保真原型，并在具体位置写标签。本文件仅约束前两步的通用操作界面；业务原型、线框内部布局、最终 UI 稿继续使用各项目的视觉来源。禁止作为根目录的全产品设计规范加载。

## 视觉方向与来源

参考 LearnUI_PM 的 Figma DESIGN.md 分析：白底黑字的界面框架、黑色胶囊主按钮、圆形图标按钮、浅绿与淡紫分区、低阴影。这里是评审工具，按操作密度转译：不照搬营销页面的大标题、整屏色块、定价卡、品牌标识和 96px 段落留白。

## 颜色与排版

可执行 Token 的单一事实源是同目录 `visual-tokens.json`。黑白用于文字与操作，浅绿表示布局阶段和确认状态，淡紫表示逐页阶段与标签工具，米黄表示尚未确认的反馈区域，浅珊瑚色表示待修改。状态同时写文字，不能只用颜色区分。

主标题 24–28px，帧标题 18–20px，正文与控件 13–14px，辅助文本 11–12px。用字重和间距区分层级，核心文字保持黑色。中文不使用负字距。figmaSans/figmaMono 未随项目提供，使用系统 UI 字体与 PingFang SC，不下载私有字体；数字使用等宽数字特性。

以 4/8px 为间距基础，常用 8、12、16、20、24、32。文本按钮 38–40px 高、胶囊圆角，触屏热区至少 44px。图标按钮正圆，输入框 8px 圆角，帧容器 24px 圆角，反馈分区 16px。静态分区以色面和细边界分层，不用玻璃、模糊、光晕或渐变；仅标签浮层和提示允许偏移柔和阴影。

## 页面结构

- 共用顶部工作台身份与阶段导航。未产出的 UI 稿只标为后续阶段，不伪装成已完成的链接。
- 布局确认：流程筛选、真实确认进度，所有关键帧在同一页单列排列；每帧左侧线框、右侧意见。线框桌面 16:9，沿用已有业务栏宽和预览样式，不让工作台配色进入线框。
- 逐页确认：左侧帧导航、中间一个真实原型 iframe、右侧确认与评论。两侧可独立收起且保留恢复按钮；收起状态延续。原型区域不透明，加载、超时和恢复入口可见。
- 标签：胶囊工具条、编号定位点、白色编辑浮层、淡紫列表工具区；保留类型、内容、回复、解决/重开、删除二次确认、导入导出。空态告诉用户如何开始。所有样式及 Token 在 Shadow DOM 内，不改变宿主产品 CSS。

## 适配与反馈

1120px 以下布局反馈区移至预览下方，逐页评论区移到画布下方；780px 以下导航与内容纵向排列，画布保留自身的可滚动区域。必须检查 1920×1034、1280×900、390×844，以及长标题、长标签、键盘焦点和放大后的恢复入口。

本地草稿与正式提交状态分开表达，不能把仅写浏览器缓存说成已同步项目。确认门、spec hash、反馈 JSON 结构、稳定锚点和业务内容不因视觉调整失效。

## 生成接线

`aipm_prototype_collab.py` 将共用 CSS 内联进两个独立页面，将 `annotation.css` 内联进标签 Shadow DOM。新项目默认读取本目录 Token；只有明确要覆盖工作台时才传 `--tokens`，不得将业务品牌 Token 自动传入。旧字段 `surface_glass*` 仅为兼容原有调用保留，默认均为实色。

改通用样式后重新运行 render-lowfi、emit-runtime/instrument、render-review；不得只手改项目 HTML。业务 spec 不变时沿用有效确认，不重新伪造审批；重新注入只更新运行时引用，核对除该引用以外业务文件内容一致。视觉验收截图放项目工作台验收目录，与业务 UI 截图分开。
