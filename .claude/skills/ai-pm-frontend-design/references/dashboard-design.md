# Dashboard Design

## 1. Dashboard Intent

生成仪表盘前先判断它服务哪个决策：

- 复盘型：解释过去发生了什么，突出趋势、异常和分层。
- 监控型：帮助快速发现问题，突出当前状态、阈值和告警。
- 经营型：面向管理层，突出目标、进度、风险和优先级。
- 产品分析型：从用户行为中发现机会，突出漏斗、路径、留存和转化。

不要把所有图都放上去。每个图必须回答一个问题。

## 2. Information Hierarchy

推荐结构：

1. 顶部概览：3-5 个关键指标，含变化方向和解释。
2. 主图区域：一张最重要的趋势/漏斗/分布图，优先占据视觉中心。
3. 诊断区域：维度拆解、异常列表、Top N 贡献项。
4. 行动区域：洞察、建议、待验证假设或后续动作。

指标卡不能只展示大数字，要说明口径、周期或变化原因。

## 3. Chart Rules

- 趋势：折线或面积图，横轴时间必须清楚。
- 漏斗：展示每步转化率和损耗，标出最大掉点。
- 排名：横向条形图优先，长标签可读。
- 分布：直方图、箱线图或分层条形图；不要用饼图承载太多分类。
- 对比：同周期、同口径；不要混用不同尺度造成误导。

Chart.js 中 `indexAxis:'y'` 必须放在 `options` 顶层。

## 4. Visual Rules

- 图表容器必须有固定高度或纵横比，避免加载后跳动。
- 颜色用于区分状态和强调，不用彩虹色堆叠。
- 异常、风险、成功、待验证要有稳定语义色。
- 复杂表格要支持扫描：列宽、对齐、排序标记、空值表达都要明确。
- 移动端优先改为纵向卡片和横向滚动图表，不硬塞桌面大表。

## 5. Business Fit

仪表盘文案必须来自业务语境：

- 教育：班级、学生、作业、掌握度、讲评、错因、知识点。
- Agent：任务、调用、置信度、人工确认、失败兜底、节省时间。
- 增长：曝光、点击、转化、留存、复购、流失风险。
- B 端效率：处理时长、待办积压、SLA、异常工单、自动化率。

不使用“指标一、指标二、测试数据、示例分类”等占位表达。
