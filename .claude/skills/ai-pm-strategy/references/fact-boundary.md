# 事实边界协议

战略沙盘必须避免幻觉与胡说。

核心规则：

> 无来源，不进结论；缺证据，只能进假设或待验证问题。

## 事实标签

| 标签 | 含义 | 能否作为结论 |
|---|---|---|
| `[用户提供]` | 用户在本轮对话中明确说过 | 可以，但需保留语境 |
| `[资料事实]` | 来自用户确认读取的项目资料 | 可以，需标来源 |
| `[用户判断]` | 用户表达的观点、倾向或判断 | 不能当作客观事实 |
| `[智囊团推演]` | 基于人物视角做的分析 | 不能当作事实 |
| `[高不确定假设]` | 涉及组织、资源、预算、商业压力等隐性信息 | 不能当作事实 |
| `[待验证]` | 当前不能判断，需要后续确认 | 不能当作事实 |
| `[不可判断]` | 信息不足，不能继续推断 | 停止推断 |

## 高不确定性维度

| 维度 | 为什么难获取 | 允许做 | 禁止做 |
|---|---|---|---|
| 组织协同 | 权责、真实态度、历史分歧通常不在文档里 | 暴露风险、列对齐问题 | 猜团队态度 |
| 资源与预算 | 人力、排期、预算动态变化 | 标资源假设 | 断言资源可用 |
| 决策链路 | 谁拍板、谁否决很隐性 | 生成决策地图草稿 | 断言拍板人意图 |
| 商业目标 | 收入、续费、客户承诺未必可见 | 区分事实和推测 | 编业务压力 |
| 客户真实声音 | PRD 常是二手转述 | 要求来源、列访谈问题 | 当作客户原话 |
| 销售/交付压力 | 前线承诺不完整沉淀 | 做待确认输入 | 替销售判断 |
| 数据可信度 | 口径、样本、埋点可能有偏 | 质疑数据支撑力 | 直接套结论 |
| 技术债/系统约束 | 文档写可做不等于复杂度低 | 问能力边界 | 给实现结论 |
| 监管/合规/品牌风险 | 内部红线不公开 | 标合规待确认 | 替法务拍板 |
| 竞品真实意图 | 只能看到动作，看不到原因 | 做情景推演 | 断言竞品目的 |
| 市场窗口 | 依赖外部和内部资源同步 | 多情景判断 | 单一确定结论 |
| 高层叙事偏好 | 老板偏好难从资料知道 | 生成多套口径 | 猜老板想法 |

## 主持人证据检查

阶段性收敛时固定输出：

```text
主持人：
当前有 3 类内容需要区分：
1. 已有事实：...
2. 推演判断：...
3. 不能判断：...
```

如果信息不足，必须说：

```text
这个问题现在不能下结论，只能形成验证清单。
```

## 写法规范

错误：

```text
研发团队会抵触这个方向。
```

正确：

```text
[高不确定假设] 该方向可能增加研发协同成本，但当前缺少研发排期、负责人态度和系统约束信息。
[待验证] 需要确认研发侧是否已有相关资源、是否存在历史技术债。
```

错误：

```text
竞品这么做是因为他们要抢占 K12 AI 入口。
```

正确：

```text
[智囊团推演] 从外部动作看，竞品可能在争夺 AI 入口心智。
[不可判断] 当前无法判断竞品真实战略意图，需要补充公开资料或一线反馈。
```

## 产出物要求

`assumptions.md` 必须包含「事实边界检查」：

```markdown
## 事实边界检查

| 内容 | 当前标签 | 来源 | 是否可作为结论 | 后续动作 |
|---|---|---|---|---|
| ... | [资料事实] | 项目 README | 是 | 可用于备忘录 |
| ... | [智囊团推演] | 本轮沙盘 | 否 | 需验证 |
| ... | [高不确定假设] | 推演 | 否 | 找负责人确认 |
```
