# 本地化适配卡（换土壤，不是翻译）

> 所有从外部借的 PM 框架，入库前**必须过这张卡**。这是一页纸过滤器，不是 pm-judgment-card 那样的大判断卡。
> 与判断卡分工：本卡管「翻译/本地化」（像不像大陆 PM、有没有翻译腔）；`pm-judgment-card.md` 管「PM 越界/altitude」（有没有写技术/视觉/算法细节）。**两张都要过。**

## 三步过滤器

每借一把"枪"，按顺序过这三步，缺一步就会重踩直译坑（初稿把 pre-mortem 直译成"事前验尸"就是漏了这道闸门）。

1. **换场景** —— 把美式案例（SaaS startup / B2C app / founder 融资）换成真实战场：B 端 / G 端 / 企业内迭代 / 试点陪跑。框架里的人物、动作、约束，都得是大陆 PM 每天面对的那些。
2. **换叙事** —— 对照下方术语表，把美式词换成大陆该说的话；更重要的是换**工作关系**：empowered（PM 全自主）→ 向上对齐 + 跨部门拉通；async memo → IM 一句话讲清 + 文档补。
3. **留内核、砍预设** —— 方法内核（如"假装已失败、倒推原因"）留下；文化预设（如"PM 自主发现一切机会""长备忘录文化"）砍掉。**判据：这一条换个公司/行业还成立吗？成立→内核，留；只在硅谷创业语境成立→预设，砍。**

## 术语换叙事对照表（入库前对一遍，发现新词就补）

| 美式原词 / 直译 | 大陆该说 | 备注 |
|---|---|---|
| pre-mortem / 事前验尸 | 上线前风险预演 | "验尸"是 post-mortem 的直译文字游戏，大陆没人这么说 |
| Opportunity Solution Tree（OST） | 机会-方案-验证拆解 | 保留 OST 当来源标签，正文用大白话 |
| discovery | 需求探索 / 需求发现 | 裸英文夹中文突兀 |
| cohort analysis | 分群留存 / 同期群分析 | |
| ship / extend / stop | 上线 / 继续观察 / 砍掉 | A/B 结论三动作 |
| battlecard | 竞品对标卡 / 销售应对卡 | "对战卡"偏游戏腔 |
| empowered team | 向上对齐为主（换的是工作关系，不只是词） | |
| async memo / 6-pager | 一句话讲清 + 文档补 | IM-first |
| North Star | 北极星指标 | 大陆已通用，保留 |
| Value / Usability / Viability / Feasibility | 值不值 / 会不会用 / 划不划算 / 做不做得出 | 4 类风险，正文用大白话，括号留英文当来源标签 |

## 一条铁律 + 标记约定

**每把枪必配一组「中国大陆反例」**（类比 phase-5 现有 7 组反例库），否则不入库。反例示范"美式直译会写成什么样 / 本地化后应该写成什么样"，**就近内嵌**在该框架自己的 reference 文件里，不搞中央反例库。

每个过卡的框架文件，**头部 YAML frontmatter 必须标**（供 doctor 机械核查，doctor 不判断内容、只查标记）：

```yaml
---
name: <框架名>
localized: true          # 过了本卡三步过滤
counter-examples: <N>    # 内嵌的大陆反例组数，必须 ≥ 1
---
```

## 入库前 checklist（5 问，全过才入库）

1. 过了三步过滤器（换场景 / 换叙事 / 留内核砍预设）？
2. 配了 ≥ 1 组大陆反例，且内嵌在本文件？
3. frontmatter 标了 `localized: true` + `counter-examples: ≥1`？
4. 过了 pm-judgment-card 越界红线（框架内容没让 PM 写技术/视觉/算法细节）？
5. 通读一遍——**像中国大陆资深 PM 写的，还是翻译腔**？只要有一句"洋味"，回到第 2 步。
