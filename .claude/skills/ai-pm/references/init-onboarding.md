# `/ai-pm init` —— 首次初始化向导

> 单一事实源。SKILL.md 路由表只放一行入口，具体流程看这里。
> 目标：新成员第一次用 AI_PM 时，2 分钟内完成「认识团队标准 → 个人微调 → 种知识库」，让之后每一份产出都更像自己、更有团队上下文。

## 设计前提（已对齐，勿擅改）

- **团队标准 = 现有内建 default**：`templates/prd-styles/default/` 模板 + `references/pm-judgment-card.md`（KettyWu 判断卡）。它**永远生效**，是「为主」的那一层，init **不负责建立它**，只负责讲明白 + 确认生效。
- **个人微调 = persona overlay**：上传过往 PRD → `persona analyze` 蒸馏五维特征，叠在团队标准之上。只影响语气/措辞/章节顺序偏好，**不覆盖团队标准的越界红线和 4 层结构**。
- **本机为主，不入库**：个人 profile 落 `templates/prd-styles/{风格名}/`，已被 `.gitignore` 挡住（含真实 PRD 原句，禁止入库）。
- **不区分角色**：init 只走「继承标准 + 个人微调 + 种知识库」。"建立/修改团队标准"是另一件事（直接改 default 模板 / 判断卡），不在 init 内。
- **三步都可跳过**，绝不做硬门槛——没有历史 PRD 语料的人也能直接开干。

## 触发方式

1. 用户显式敲 `/ai-pm init`
2. 欢迎区首次检测（见 `session-start.sh`）：无项目 + 无 `.active-persona` 时，提示「建议先 `/ai-pm init`」，但不强制。

## 流程（KettyWu 主持，说人话，一次只问一件事）

### 开场（一句话讲清这是什么）
> 「第一次用，我带你花 2 分钟做个初始化。做完之后我写 PRD 会更像你的手笔、也带着团队的上下文。三步，每步都能跳过。」

### 第 1 步 · 认识团队标准（0 操作，只讲）
告诉用户：
- 「不管谁来写，PRD 都以**团队标准**为底——一套内建模板 + 一位有洁癖的资深 PM（KettyWu）的判断卡：技术细节不瞎写、验收标准不含糊、不写'建议考虑'这种废话。」
- 「这套已经生效，你不用做任何事。下面两步是在它之上，**叠你自己的东西**。」

### 第 2 步 · 上传历史 PRD（可选，推荐）—— 一步同时做三件事

引导：
> 「把你过往写得最满意的 2-5 份 PRD 的文件路径给我（.md / .txt 都行）。我会学你的写法、把它们归档下来、之后还能转成项目继续做。没有也没关系，直接说'跳过'，先用团队标准。」

用户给路径后，对每一份**同时**做两件机械动作（不猜、不判断归属）：

1. **学风格（目标①）** → 调 `ai-pm-persona` 的 `analyze [路径]`（同一风格名累积多份，默认 `{用户名}-个人`）→ 存 `templates/prd-styles/{风格名}/style-profile.json`（本机，已 gitignore）→ `persona apply {风格名}` 设为生效。
2. **归档语料（目标②）** → 复制进本机语料库 `output/_prd-corpus/`（原文件不动）。这里的 PRD 是**学习/参考语料**，不是活跃项目，所以**不放 `output/projects/`、不进 `/ai-pm list`**。也作为第 3 步知识库提炼的来源。

**必说的三句**：
- 边界：「风格是叠加，不是替换。团队标准的越界红线、4 层结构永远优先，你的风格只调语气和章节偏好。」
- 隐私：「风格档案 + 归档的 PRD 都只存你本机（`output/` 整体不入库），含原句，不会进 git、不会上传。」
- 后续：「想把其中某份**转成项目继续迭代**？用 `/ai-pm import <语料库里的PRD>`，我提议项目名你确认后立项——见目标③。init 本身不批量立项，避免一次生成一堆项目。」

跳过分支：不 analyze、不归档，`.active-persona` 不创建，写 PRD 时纯用团队标准。

> **目标③（继续迭代老 PRD）由 `/ai-pm import` 承担，不在 init 自动做。** import 是确认制立项：读 PRD → 提议项目名/版本 → 用户确认/改名/合并 → 建 `output/projects/{名}/` 标准骨架，PRD 落 `05-prd/05-PRD-v{n}.md`，当前阶段标「PRD 完成/待原型」。**只从 05-prd 播种，不倒推 01-04 上游内容**（倒推=伪造 PRD 前传，踩"不脑补"红线）；上游文件夹按约定建出但留空，用户要补再显式跑对应阶段、且标 AI 推断待确认。详见 SKILL.md「`/ai-pm import`」节。

### 第 3 步 · 种知识库（可选，推荐）
1. 说明：「知识库现在是空的。种一点进去，以后遇到类似问题我能直接提醒你'上次怎么决定的'。」
2. 两个来源，问用户走哪个（或都跳过）：
   - **从刚上传的 PRD / 历史项目提炼**：我读一遍，挑几条方法论 / 踩坑 / 决策，逐条念给你确认后入库。
   - **你口述团队约定**：你说几条（如"PRD 不写技术栈""话术不透版本号"），我记成卡片。
3. 确认后调 `ai-pm-knowledge` 的 `add` 写入对应分类（decisions / insights / patterns / pitfalls / playbooks / metrics）。
4. 知识库内容同样本机不入库（已 gitignore）。

### 收尾 · 初始化小结
输出一张清单，并指下一步：

```
✅ 初始化完成
─────────────────────────
团队标准   ✓ 已生效（内建 default + KettyWu 判断卡）
个人风格   {已学 N 份 PRD，生效中 ｜ 已跳过，用团队标准}
语料库     {N 份 PRD 已归档到 output/_prd-corpus/ ｜ 未上传}
知识库     {已种 N 条 ｜ 暂空，以后随时 /ai-pm knowledge add}
─────────────────────────
下一步：开始你的第一个项目
  /ai-pm [一句话需求]
想继续做某份老 PRD？
  /ai-pm import <output/_prd-corpus/里的PRD>
```

## 与现有命令的关系（不重复造轮子）

| init 步骤 | 复用的现有能力 | init 的增量 |
|-----------|---------------|------------|
| 第 1 步 | pm-judgment-card / default 模板 | 纯讲解，让"为主+微调"的分层关系被用户理解 |
| 第 2 步 · 学风格 | `/ai-pm persona analyze` / `apply` | 把"上传哪些、命名、apply、隐私话术"包装成引导，省得用户自己拼命令 |
| 第 2 步 · 归档语料 | —（新增 `output/_prd-corpus/`） | 上传的 PRD 机械复制归档，作为语料 + 知识库提炼来源 |
| 第 3 步 | `/ai-pm knowledge add` | 主动提议来源 + 从历史 PRD 提炼，而非等用户想起来记 |
| 关联命令 | —（新增 `/ai-pm import`） | 确认制把语料库里的 PRD 立项为正式 project，不在 init 自动做 |

init 主体是**编排层**（复用 persona/knowledge）；本次新增两处轻量能力：`output/_prd-corpus/` 语料库（机械归档，无新存储格式）+ `/ai-pm import` 立项命令（确认制，复用 `/ai-pm new` 的项目骨架生成）。
