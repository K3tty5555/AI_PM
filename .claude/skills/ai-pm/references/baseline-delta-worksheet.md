# 基线 delta 工作表（迭代项目专用）

## 核心 insight

**迭代项目的需求 = delta，不是新功能。**

写 PRD 的根本问题不是「这个新功能怎么设计」，而是「老系统今天做的事，新版上线后会变成什么；用户/运营/系统的哪些行为会被影响」。

跳过这一步直接写 PRD，必然遗漏一类坑：**老系统能做但新流程缺**、**老系统的某个隐性步骤新流程没承接**、**老系统的某个角色（运营/客服）不知道功能下线**。

## 谁该用这份工作表

迭代型项目（任一满足）：
- `07-references/` 目录非空（用户已放入历史文档）
- `_memory/L1-decisions.md` 提及历史版本（V1/V2/老版本等）
- 用户需求中含「迭代 / 扩展 / 兼容老 / 接入老 / V2/V3」等关键词

0→1 项目不需要这张表，按现有 Phase 1 流程走。

## 三类高密度避坑信息（资料阅读重点）

读老系统资料时，重点扫这三类：

### 1. 老 PRD 里的「异常流 / 配置依赖 / 互斥规则 / 补充说明 / 注：」

这些是老系统隐性约束的集中地。常见格式：
- 「**互斥规则**：A 功能开启时 B 自动关闭」
- 「**补充说明**：需先完成 X 才能使用 Y」
- 「**注**：本功能受 X 权限控制」

新版上线后，这些约束怎么变？保留、删除、还是反过来？每一条都要在 delta 表里有交代。

### 2. 操作手册里所有「需先 X」「需手动 Y」的隐性步骤

操作手册里的每一个「手动操作步骤」都是潜在坑：
- 「需先完成定标，才能开启批改」
- 「需手动添加小空，绑定题号后才能保存」
- 「需先上传模板，才能创建考试」

新流程把这些步骤砍了？还是替换了？还是保留？砍掉时用户感知怎么处理？

### 3. 运营/客服已知的「下线即问」功能

某些功能即使产品认为「下线不影响」，运营/客服会在第一天接到问询电话：
- 「为什么找不到 X 入口了？」
- 「为什么这次配置和上次不一样？」

判断标准：老系统里**有独立入口、有专门话术、教师习惯用**的功能，下线就要出客服 SOP。

## 工作表结构

```
| 老系统行为 | 新系统对应 | 用户感知差异 | PRD 干预 |
|----------|----------|------------|---------|
| {老系统做什么}  | {新版做什么 / 取消 / 替换}  | {用户/运营/客服会感觉到什么}  | {§几补什么 / 不干预原因} |
```

**四列含义**：

- **老系统行为**：从老 PRD/手册里抄出来的具体行为（一个功能、一个配置项、一个操作步骤）
- **新系统对应**：本期新流程下对应做什么。可能值：保留、取消、替换为 X、缺失（这是坑）
- **用户感知差异**：用户/运营/客服会不会觉察到这个变化？怎么觉察？
- **PRD 干预**：在 PRD 的哪个章节做处理，或注明「不干预」的理由

## 填表自检（每一行必过）

- [ ] **老系统行为**列写的是具体行为，不是「老系统的批改」这种笼统词
- [ ] **新系统对应**列不允许写「待定」「不确定」，必须明确：保留 / 取消 / 替换 / 缺失
- [ ] 当对应列为「缺失」时，第 4 列必须有产品干预方案（添加该功能 或 明确暂不支持的话术）
- [ ] **用户感知差异**列不能空——即使是后台静默变更，也要写「无感知（运营后台操作，非用户行为）」
- [ ] **PRD 干预**列引用具体章节号或附录条目，不能写「在 PRD 里说一下」这种话

## 完整示例（取自 AI批改助手 V3——旧版答题卡支持新版AI批改）

| 老系统行为 | 新系统对应 | 用户感知差异 | PRD 干预 |
|----------|----------|------------|---------|
| 旧版答题卡大题坐标已记录，但大带小子空坐标未单独记录（操作手册：科组长手动添加小空） | 缺失——若仅做坐标转置，大带小题型无法批改 | 配置后批改失败、教师困惑 | §5.2 新增「添加小空」配置步骤（旧版答题卡大带小填空题前置） |
| 英语作文「定标」入口（操作手册：教师必须先完成定标才能开启批改） | 取消（新版AI批改不需要定标） | 教师找定标入口找不到 → 致电客服 | §7.4.3 客服 SOP：教师询问统一回复「已升级为新版AI批改，无需定标」 |
| 旧版AI批改配置（V2 已配过的语文作文题） | 静默清空 | 无感知（权限由运营/技术支持后台操作，非用户行为） | §7.1 说明触发源 + 静默理由 |
| 旧版AI批改语文作文有独立报告 | 复用新版AI批改报告页（V1/V2 已有） | 无感知（报告页一致） | 不干预——§4.2 复用对照表注明 |
| 老 PRD §6.1：新旧 AI 批改入口互斥规则 | 保留（权限开通即互斥） | 无感知 | §7.1 兼容性章节继承互斥规则 |

空 mitigation 列 = 未覆盖的坑。**填表过程本身就是找坑过程。**

## 与 Phase 5 的衔接

Phase 5（PRD 生成）开始时，强制检查 `01-baseline-delta.md`：

- 迭代项目 + 文件不存在 → 阻断，回到 Phase 1 补
- 迭代项目 + 文件存在但有未填写行 → 阻断，回到 Phase 1 补
- 0→1 项目 → 跳过此检查
