# 约定包模板（`05-prd/ai-md/_conventions.md`）

> WS0 产出物的通用结构模板。给 PRD 起草前的扎根注入用：**项目有约定的地方别发明**。
> 本模板只含通用占位示例（某 K12 教育平台风格），真实项目的约定包落在 `output/projects/{项目}/05-prd/ai-md/_conventions.md`（不入库）。
> 抽取尽量走确定性命令（各节附）；`build_conventions.py` 可机械产出草稿，模型整理后人工挑一遍固化。

## 0. 定稿分级规则（约定的权重，先看这节）

PRD 是否定稿没有完美判据，用**保守取证**（按序，拿不准一律降为草稿级）：
1. `README.md` 版本表**状态列**（如「A 级定稿 / 草稿待评审」）
2. PRD 内**修订日志**是否含「评审通过」行
3. **PDF 分发件**默认视为历史定稿（导出分发本身是给人看过的信号）

**注入权重**：
- **A 级（已评审定稿）** = 项目约定，起草时违背要显式标理由
- **草稿级** = 仅参考，注入时标「来自草稿，未经评审」，不当硬约定
- **机器抽取件** = 骨架/术语可信、具体事实（日期/表格数值）不可信
- **已归档（⛔）** = 只当词源/写法参考，不当需求依据

## 2. 章节骨架约定（注入用）

> 抽取命令：原生 `grep -nE "^#{1,3} "`；抽取件 `grep -nE "^[一二三四五六七八九十]+、|^[0-9]+\.[0-9]+、"`

```
一、文档概述（1.1 评审/修订日志）
二、需求分析（2.1 背景 / 2.2 价值 / 2.3 成功指标）
三、功能清单
四、全局说明（复用对照表 / 影响范围 / 按版本性质选用）
五、详细功能设计（5.x 按页面/场景切小节）
六/七、非功能性说明、暂不纳入本期、待对齐 …（按项目实际）
```

**命名惯例**：文件名 `[YYYYMM][域]标题`；大章中文序号、小节 N.N（按项目实际记录）。
