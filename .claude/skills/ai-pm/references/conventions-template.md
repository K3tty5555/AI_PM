# 约定包模板（`05-prd/ai-md/_conventions.md`）

> WS0 产出物的通用结构模板。给 PRD 起草前的扎根注入用：**项目有约定的地方别发明**。
> 本模板只含通用占位示例（某 K12 教育平台风格），真实项目的约定包落在 `output/projects/{项目}/05-prd/ai-md/_conventions.md`（不入库）。
> 抽取尽量走确定性命令（各节附）；`build_conventions.py` 可机械产出草稿，模型整理后人工挑一遍固化。
>
> ⚠️ **live 回写纪律（2026-06-15 增，重要）**：约定包是历史语料的**一次性蒸馏快照、单向静态**——PRD 起草/评审中用户**当场推翻或新定**某条约定（重定义路线、改命名、改 scope）时，**当场回写本约定包对应项**（记进下方 §6 live 决策约定，标 `来源=live决策 + 末次确认日`），别等 lint 事后抓。grounding 源滞后于 live 决策 → lint 会拿过期约定包判 PRD"错"（实证：2026-06-15 路线"四级→两路线"live 重定义未及时回写，driver 误判 PRD stale、要改回旧四级体系）。**冲突时 live 决策 > 历史推定。**

## 0. 定稿分级规则（约定的权重，先看这节）

PRD 是否定稿没有完美判据，用**保守取证**（按序，拿不准一律降为草稿级）：
1. `README.md` 版本表**状态列**（如「A 级定稿 / 草稿待评审」）
2. PRD 内**修订日志**是否含「评审通过」行
3. **PDF 分发件**默认视为历史定稿（导出分发本身是给人看过的信号）

**注入权重**：
- **A 级（已评审定稿）** = 项目约定，起草时违背要显式标理由
- **草稿级** = 仅参考，注入时标「来自草稿，未经评审」，不当硬约定
- **机器抽取件** = 骨架/术语可信、具体事实（日期/表格数值）不可信
- **已归档（⛔）** = 只当词源/写法参考，不当需求依据
- **live 决策（最高权重）** = 用户对话中当场拍的约定（重定义路线/改命名/改 scope），权重 > 历史语料的任何推定；必带 `来源=live决策 + 末次确认日`、记进 §6，与历史推定冲突以它为准（见顶部 live 回写纪律）。lint/pm-agent 读约定包时，§6 live 项压过上面各节的历史推定

## 2. 章节骨架约定（注入用）

> 抽取命令：原生 `grep -nE "^#{1,3} "`；抽取件 `grep -nE "^[一二三四五六七八九十]+、|^[0-9]+\.[0-9]+、"`

```
一、文档概述（1.1 评审/修订日志）
二、需求分析（2.1 背景 / 2.2 价值 / 2.3 成功指标）
三、功能清单
四、全局说明（复用对照表 / 影响范围 / 按版本性质选用）
五、详细功能设计（5.x 按页面/场景切小节）
六/七、非功能性说明、暂不纳入本期、待对齐 …（按项目实际）
```

**命名惯例**：文件名 `[YYYYMM][域]标题`；大章中文序号、小节 N.N（按项目实际记录）。

## 3. 术语与动作名（权威词表，发明新词必须显式标理由）

> 抽取命令：加粗词 `grep -oE '\*\*[^*]+\*\*'` 频次、「」内动作名频次、核心域词计数。**候选限定来源**：标题、加粗词、「」内动作名、§词典、按钮/状态/流程名——不拿裸高频词（中文泛词误报高）。

**核心域词（全语料频次）**：{词 A} N / {词 B} N / …
**高频动作/状态名（「」内，UI 真名）**：「{动作名}」N / …
**已证伪的生造词（绝不用）**：{词} —— {证据：历史 0 命中，团队全程说「{真名}」}
**弃用某用法但保留另一用法的词（带负排除，别一刀切词）**：{词} —— 弃用「{用法 A，如作方案命名}」（{理由，如 business 听不懂 native}）／**保留**「{用法 B，如"天然支持"日常义}」（负排除）。
