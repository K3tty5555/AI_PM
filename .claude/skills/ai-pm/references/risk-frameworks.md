# 上线前风险预演（pre-mortem 本地化）

> 已过 `localization-card.md` 三步过滤。这是 phase-8 评审前的强制前置步，不是新命令。

## 它是什么、不是什么

- **是**：评审前，全组**假装这个功能已经上线、并且彻底失败了**，从"已经死了"倒推"为什么会死"。往前看的预防动作。
- **不是 phase-9 复盘**：复盘是上线后**往后看**真实发生了什么；风险预演是上线前**往前看**假装的失败。两者不能混。
- **不是六角色评审**：六角色是逐条挑"写出来的 PRD 哪里不对"；风险预演是凭空生成"还没写进 PRD 的死法"。先做风险预演，把死法喂给六角色评审。

## 硬触发（防沉睡）

**每次进 phase-8，强制跑「红线/合规槽位」这一维**——这一维不可省。其余维度按规模可详可略：单功能补丁扫一遍即可，复杂/Agent 功能逐维倒推。

## 红线/合规槽位（通用声明，内容由行业包填）

⚠️ **核心只声明"必须查红线"，不写任何具体行业的红线内容。** 具体红线是 `pack[行业]` 的事（见 industry-pack 机制）——核心写死某行业红线 = 把通用的枪焊成垂类专用。

通用问法：**这个产品/行业，有没有不能碰的红线？**（数据安全 / 合规资质 / 伦理 / 特殊人群保护 / 行业监管）。当前项目的行业包若已声明红线，逐条对照本期改动；没有包就当面问业务方一句。

## 倒推维度（8 类风险，已换大陆说法）

逐维问"如果它死在这，会是怎么死的？"——括号里留英文当来源标签：

| 维度 | 大陆问法 |
|---|---|
| 值不值（Value） | 用户根本不用 / 用了一次不回来，会是因为什么？ |
| 会不会用（Usability） | 用户找不到入口 / 不会用 / 嫌麻烦，卡在哪一步？ |
| 划不划算（Viability） | 成本兜不住 / 卖不动 / 撑不住量 / 客户用不起来，哪头先崩？ |
| 做不做得出（Feasibility） | 现有能力做不到 / 集成打不通——**这条只标"存疑、待研发对齐"，不替研发下结论** |
| 红线（Ethics + 合规） | 见上方红线槽位，强制 |
| 怎么推（GTM） | 渠道够不够 / 试点推不动 / 时机不对 / 上线方式错了 |
| 战略（Strategy） | 解的是不是真问题 / 会不会被轻易抄走 / 政策经济环境变了 |
| 团队（Team） | 协作 / 人手 / 工具跟不上，哪块拖死它 |

## 输出（接给六角色评审）

一张风险清单，按本期规模详略：

| 风险（怎么死的） | 会怎么暴露（用户/业务侧能感知的信号） | 严重度 | 谁来防 | 兜底 |
|---|---|---|---|---|

- "怎么暴露"只写**用户或业务方能感知**的失败（用了不回来、试点推不动、红线被踩），不写接口超时/缓存未命中这类研发自决项。
- "谁来防/兜底"是分工与替代方案，不是技术方案。

## 大陆反例（内嵌，2 组）

**反例 1 · 标题直译**
- ❌ 美式直译：「Pre-mortem（事前验尸）：团队 conduct 一次 failure 推演……」
- ✅ 本地化：「上线前风险预演：评审前，全组假装这功能已经上线、彻底失败了，倒推为什么会死。」

**反例 2 · 把行业红线焊进核心**
- ❌ 焊死：核心文件直接写「pre-mortem 必须检查未成年人数据合规」——这把通用框架定制成了教育专用，金融/电商项目跑起来就是噪声。
- ✅ 槽位化：核心只写「必须查『红线/合规槽位』」，内容交给 `pack[教育]` 填"未成年人数据/考试公平"、`pack[金融]` 填"风控/适当性"。换个行业，框架照样成立。
