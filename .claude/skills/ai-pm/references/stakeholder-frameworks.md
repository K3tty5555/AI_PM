# 协作地图 + 客户决策地图（stakeholder map 本地化）

> 已过 `localization-card.md` 三步过滤。扩进 ai-pm-analyze，不是新命令。
> 一个需求产**两张分开管理**的图：**协作地图（内）** + **客户决策地图（外）**。

## 换土壤（砍美式预设）

砍掉「权力×兴趣」2×2 网格黑话。美式 empowered team（PM 自主拍板）→ 大陆现实是**向上对齐为主 + 横向拉通 +（B/G 端）外部客户多层决策链**。这正是「换土壤」最该换的工作关系，不只是换词。

## 硬触发（防沉睡）

需求**涉及多团队 / 要过会或向上汇报 / 有外部客户决策链**时，产这两张图；纯个人小改、单团队内部迭代不触发。

## 协作地图（内部）

把这事做成，内部要拉谁、向谁汇报。三栏：

| 角色 | 他关心什么 | 怎么沟通 |
|---|---|---|
| **向上**：老板 / 业务负责人 | ROI、资源占用、风险 | 重点对齐（争资源、要拍板） |
| **横向**：研发 / 测试 / 设计 / 运营 / 销售 / 客户成功 | 排期、可行性、上线协同 | 定期同步 / 拉通 / 知会一声 |

沟通方式只用三档：**重点对齐 / 定期同步 / 知会一声**——别照搬美式那套层层细分。

## 客户决策地图（外部 · B/G 端）

⚠️ **核心只声明通用四类角色，不焊任何具体行业的层级**（具体层级由示例 / 行业包给）：

| 客户侧角色 | 是谁 | 我们要让他怎样 |
|---|---|---|
| **决策者** | 拍板买/用的人 | 认价值、肯签 |
| **影响者** | 左右决策的人 | 站我们这边 |
| **使用者** | 真正天天用的人 | 用得顺、愿留 |
| **阻碍者** | 能卡住的人 | 化解顾虑 / 绕开 |

## PM altitude（守住）

这是协作与沟通规划，不写技术实现；角色按**真实组织**填，不脑补头衔（呼应「PRD 不能脑补名词」——拿不准的角色先问再写）。

## 输出

接进需求分析报告，新增「协作与决策地图」小节（两张图分列），喂给后续推进 / 评审 / 上线协同。

## 大陆反例（内嵌，2 组）

**反例 1 · 权力×兴趣网格直译**
- ❌ 美式直译：「按 Power×Interest 四象限分：高权力高兴趣 = Manage Closely，低权力高兴趣 = Keep Informed……」
- ✅ 本地化：拆成两张大白话图——内部「老板(关心 ROI，重点对齐) / 研发负责人(关心排期，定期同步)」，外部「谁拍板 / 谁影响 / 谁用 / 谁能卡」。

**反例 2 · 把行业决策链焊进核心**
- ❌ 焊死：核心直接写「外部决策链 = 教育局 → 校长 → 教研组长 → 一线老师」——这把通用框架定制成教育专用，集团里金融/政务团队拿到就是噪声。
- ✅ 槽位化：核心只写通用四类（决策者/影响者/使用者/阻碍者），具体层级作示例——「如教育 G 端：教育局/校长(决策者)、教研组长(影响者)、一线老师(使用者)；如金融：业务负责人(决策者)、风控(阻碍者)、一线柜员(使用者)」。换个行业，框架照样成立。
