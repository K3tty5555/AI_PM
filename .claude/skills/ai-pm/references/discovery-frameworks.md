# 假设-验证纪律（discovery 本地化）

> 已过 `localization-card.md` 三步过滤。这是 ai-pm-analyze 的一个加层，不是新命令。
> 补的是 ai-pm-analyze 唯独缺的那块：痛点分级/MoSCoW/北极星都有了，**就差"我们在赌什么 + 怎么花小代价先验"**。

## 本地化前提（换场景：承认需求多自上而下）

美式 discovery 假设"PM 自主发现机会"。大陆现实是需求多由老板/业务/客户给定。**所以纪律不在"PM 发现一切"，而在**：哪怕需求是老板拍的，也要把它**没说出口的假设**标清楚，并说清"怎么花小代价先验"——而不是直接全量开发完再看数据。

## 硬触发（防沉睡）

需求含**新场景 / 新用户行为**时，**强制**标假设 + 怎么验。纯参数调整 / 修 bug / 加开关类迭代**不触发**——别为填表而填。

## 三步做法

**第 1 步 · 标假设**：这个需求要成立，我们在赌哪几条**还没验证**的事？按维度扫（括号留英文当来源标签）：

| 维度 | 在赌什么 |
|---|---|
| 值不值（Value） | 赌用户真有这个痛、且愿意为这个解法买单/持续用 |
| 会不会用（Usability） | 赌用户找得到、学得会、不嫌烦 |
| 划不划算（Viability） | 赌成本兜得住、卖得动、撑得住量、合规 |
| 做不做得出（Feasibility） | 赌现有能力做得到——**只标"存疑、待研发对齐"，不替研发拍** |
| 怎么推（GTM） | 赌渠道够、试点推得动、时机对 |
| 战略（Strategy） | 赌解的是真问题、不会被轻易抄走 |
| 团队（Team） | 赌人手 / 协作 / 工具跟得上 |

**第 2 步 · 标信心**：每条假设标"已验证 / 半信半疑 / 纯赌"。把火力集中在"纯赌 + 一旦错代价大"的那几条。

**第 3 步 · 怎么花小代价先验**：每条高风险假设配一个**轻验证**——灰度放量 / 单点（如单店/单班/单团队）试点 / 埋点看真实行为 / 几个真实用户访谈 / 拉历史数据。**先验再开发，不是开发完再验。**

## 输出（接到 ai-pm-analyze §6 约束与风险）

| 假设（我们在赌……） | 信心 | 怎么先验（轻验证） |
|---|---|---|

落进需求分析报告，喂给后续 PRD 和上线前风险预演（[[risk-frameworks]]）。

## 大陆反例（内嵌，2 组）

**反例 1 · 直搬"PM 自主发现"**
- ❌ 美式直译：「通过 continuous discovery，PM 自主发现 opportunity，决定 what to build。」
- ✅ 本地化：「需求多是老板/业务给定的——我们不假装能自主发现一切，但哪怕老板拍的，也得标清它在赌什么、怎么先验。」

**反例 2 · 裸框架名 + 验证缺位**
- ❌ 洋味 + 空：「识别 Value/Usability/Viability/Feasibility 四类 risk。」然后就没了，没说怎么验。
- ✅ 落地：「赌老师愿意用 AI 批改替代手批（值不值，纯赌）→ 先在 1 个班灰度两周，看回收率和复用率，再决定要不要铺开。」每条假设都接一个能跑的轻验证。
