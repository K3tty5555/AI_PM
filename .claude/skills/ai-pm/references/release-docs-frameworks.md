# 上线文档套件（release-notes 本地化）

> 已过 `localization-card.md` 三步过滤。被 `/ai-pm release-docs` 命令调用，是该命令的方法内核。

## 换土壤（砍美式预设）

原版 release-notes **保留版本号**（"V1.5 ships X"）。本地化**反向删掉版本号 / 上线时间 / 内部代号**——挂死 `feedback_no_version_in_user_speech` 铁律：给用户的话不透 V1.x、不透上线时间、不透「下个迭代」。技术黑话翻成用户听得懂的人话。

且长成**大陆原生**：发**飞书云文档**（IM-first 现实），不是发邮件 / changelog 站点。

## 两份产物

**① 更新公告（短）**：用户能感知的变化，每条「现在能 X 了 / X 变得更 Y 了」。不提版本号、不提技术、不提时间承诺。控制在用户扫一眼就懂。

**② 操作手册（分步）**：新功能怎么用——分步骤（进入哪 → 点哪 → 看到啥 → 下一步），给一线用户能照着做的 how-to。每个新功能一段，复杂的配截图位 `[截图：xxx]`。

## 来源与中立

- 来源：本期 PRD / 原型 / **实际上线功能**（以实际上线为准，PRD 是参考——没上线的别写进去，否则成空头支票）。
- 行业中立：手册示例用通用占位 / 用户角色用槽位（「用户 / 一线人员」），不焊教育，保证全行业可分享。

## PM altitude（守住）

不写技术实现；手册是**用户操作视角**，不是研发文档；交互文案过 humanizer-pm 去 AI 味。

## 大陆反例（内嵌，2 组）

**反例 1 · 保留版本号 / 时间承诺**（用通用/客服场景，避免全篇教育味）
- ❌：「V2.0 上线！新增批量导出，预计下月覆盖全部客户。」
- ✅：「现在能批量导出了——勾选后一键导出 Excel，不用一条条复制。」（无版本号、无时间、无承诺）

**反例 2 · 技术 changelog 当用户文档**
- ❌：「优化了检索接口性能，重构了索引模块，降低了 P99 延迟。」
- ✅：「找题更快了——以前要等几秒，现在基本秒出。」（只讲用户感知得到的，说人话）
