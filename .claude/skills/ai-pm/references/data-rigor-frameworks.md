# 数据严谨度三件套（cohort / 留存曲线 / A-B 显著性 本地化）

> 已过 `localization-card.md` 三步过滤。这是 ai-pm-data 的一个加层，不是新命令。
> 补的是 ai-pm-data 唯独缺的那块：能做指标/洞察/仪表盘了，**就差"区分真信号和噪声、看真实粘性而非虚荣指标"**。

## 硬触发（防沉睡）

只在**真做留存分析**或**真跑 A/B 实验**时 pull——普通描述统计 / 趋势 / 仪表盘**不触发**，别给每个数据任务都套严谨度仪式。

## 三件套

**① 分群留存（cohort）**：把用户按"同一批次进来的"分组（按注册周 / 首用周 / 试点批次），**各组分别看留存**，而不是看一个被新用户稀释的整体留存率。整体留存率会被持续涌入的新用户撑高、掩盖老用户在流失——分群才看得清每一批人到底留没留住。

**② 留存曲线**：一批人从第 1 天/周到第 N 天/周还剩多少在用，画成曲线。看两件事：**哪天开始走平**、**走平在什么水平**。跌到底然后**走平**=有真实粘性；**一路跌到 0**=只是尝鲜不留人。

**③ A-B 显著性**：A 组旧、B 组新，看新版指标更好——但关键是**这差异是真的，还是抽样噪声**。PM 层要盯三件事：样本量够不够、最小可检验差异（MDE，能稳定看出的最小差距）、置信够不够。结论三动作（换叙事 ship/extend/stop）：**上线 / 继续观察 / 砍掉**。

## PM altitude（守住，别越界）

PM 只到**业务判断**层：要不要做显著性检验、样本够不够下结论、结论是上线还是砍。**具体用哪种检验、MDE/样本量怎么算、p 值阈值取多少——由数据侧定，PM 不写。** 这跟"做不做得出由研发对齐"一个道理。

## 输出

接进 `09-analytics/data-insight-report.md`（洞察）或 `09-analytics/analytics-requirement.md`（A/B 设计），用业务语言写结论 + 对应动作，不写统计实现。

## 大陆反例（内嵌，2 组）

**反例 1 · 虚荣指标当健康**
- ❌：「整体留存率 60%，很健康，不用管。」
- ✅：「分群看——3 月那批第 4 周走平在 40%（有粘性），5 月那批还在一路跌；整体 60% 是被新用户撑高的虚高，老用户其实在流失。」

**反例 2 · 赌噪声就上线**
- ❌：「新版点击率比旧版高 3 个点，上！」
- ✅：「样本才 200，这 3 个点在噪声范围内、还没到能稳定看出的差距（MDE）。先继续观察到样本够，再判上线还是砍——别拿波动当效果。」
