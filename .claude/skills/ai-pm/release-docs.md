# `/ai-pm release-docs` —— 上线文档套件（公告 + 手册 + 飞书发布）

## 命令

`/ai-pm release-docs [PRD路径 | 项目名]`

## 功能

基于**实际上线功能**，产两份给用户的文档——**更新公告**（短）+ **操作手册**（分步），并可发到飞书云文档。方法内核（含换土壤 + 大陆反例）单一事实源在 `references/release-docs-frameworks.md`，本文件只描述命令流程。

## 流程

**Step 1 · 取来源**
- 读本期 PRD（`05-prd/` 最新版）+ 原型（如有）。
- **以实际上线为准**：问用户「这版**真上线**了哪些功能？」——没上线的不写进文档（否则成空头支票）。

**Step 2 · 生成两份 md**
- 读 `references/release-docs-frameworks.md`，按其方法产：
  - `13-release-docs/{日期}-更新公告.md`
  - `13-release-docs/{日期}-操作手册.md`
- 落 `output/projects/{项目名}/13-release-docs/` 下。

**Step 3 · 铁律自检 + 去 AI 味**
- 扫两份文档：出现**版本号 / 上线时间 / 内部代号**→ 删（`feedback_no_version_in_user_speech`）。
- 交互/面向用户文案过 **Humanizer-zh**。

**Step 4 · 飞书发布（先确认，再发；记住项目偏好）**
1. 先把 md 给用户过目，**等用户确认**（发布是对外动作，不可逆，默认先确认）。
2. 查该项目飞书发布偏好（`_memory/` 或 `_status.json` 的 `lark_publish_pref`）：
   - **已记** → 默认沿用（建新 / 更新指定文档 token），不再问。
   - **未记** → 问用户「**建新云文档**，还是**更新已有**（给文档链接）？」，把选择 + 目标文档 token **记住**，后续默认沿用。
3. 调 **lark-markdown / lark-doc** 技能发飞书：建新则创建并返回链接；更新则按记住的文档 token 覆盖更新。
4. **lark-cli 未配置**（见 `lark-shared`）→ 退化：只出本地 md + 提示「飞书未配置，先 `lark-cli config init` / `auth login`，或手动发」，不中断。

**Step 5 · 输出**
- 报本地文件路径 + 飞书链接（若已发）。

## 注意事项

- 不透版本号 / 上线时间 / 内部代号——铁律，自检必扫。
- 以实际上线为准，不脑补未上线功能。
- 发布是对外动作：默认先出 md 确认再发，不自动直发。
- 行业中立：用户角色用槽位（用户 / 一线人员），不焊具体行业。
