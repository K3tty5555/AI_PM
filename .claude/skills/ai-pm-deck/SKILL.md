# 分享与汇报材料（演讲用）

## 先分清：讲 ≠ 写

`ai-pm-sharing` 产出**文章**：读者可以回看、跳读、慢慢想。
本 skill 产出**演讲材料**：听众只有一次机会，跟不上就掉队。

两者的信息密度、结构、语言全部不同。**把文章切成页放上幻灯片，是最常见的失败方式。**

## 三件套与分工

| 产物 | 回答什么 | 放什么 | 落盘位置 |
| --- | --- | --- | --- |
| **讲者稿** | 怎么讲 | 每页口播词、取舍理由、追问准备、上台纪律 | `{项目}/汇报大纲-{版本}.md` |
| **叙事大纲** | 讲什么 | 骨架 + 实例 + 每段结论，给别人读、自己临场扫 | `{项目}/云文档增强版-{版本}.md` |
| **幻灯片** | 展示什么 | 只放锚点：一个观点、一块视觉、一句落点 | `{项目}/publish/{名称}.html` |

**三者必须同步。** 改一处要三处一起改——页面上的措辞和你要讲的话对不上，听众会分神。

## 流程

### 1. 先定听众和目的，再动结构

这两件事决定叙事骨架，问清楚再开工：

- **听众是谁**：纯领导 / 同侪 / 跨部门 / 混合。**不要假设他们听过前置分享**；
- **听完你要他们做什么**：认可、决策、了解、还是照着做；
- **时长与页数**：20 分钟约 9 页，每页 1–3.5 分钟。

### 2. 立骨架：三段论

现象 → 原因 → 应对。缺任何一段，听众都会在中途问"所以呢"。

**因果链必须闭合。** 常见断裂：讲完问题直接跳到方案，没说清"为什么这个方案能解决这个问题"。听众会觉得你只是在多干活。

### 3. 找实例：这一步最容易翻车

见下方「实例纪律」。**先核实出处，再写进材料。**

### 4. 落页面：从骨架起步，不要从零写 CSS

```bash
cp .claude/skills/ai-pm-deck/templates/deck-skeleton.html {项目}/publish/{名称}.html
```

骨架里已经内建：中文黑体字体栈、三段式版式、四档响应式（含 720p 投屏专门收紧）、
键盘/触屏翻页、五色语义系统，以及常用组件（两栏对照、三列表、卡片组、议题条、原话卡）。
文件末尾的注释里有组件速查，按需复制到 `.body-area` 内。

排版原则见下方「页面设计」。

### 5. 质检

```bash
python3 .claude/skills/ai-pm-deck/scripts/check_deck.py <deck.html> \
    --deny "内部代号,业务专名,行话" --shots ./_private/deck-shots
```

脚本查版面、密度、语言、出图；**版式好不好看它判断不了，截图务必自己翻一遍。**

### 6. 导出（可选）

```bash
python3 .claude/skills/ai-pm-deck/scripts/export_pptx.py <deck.html>
```

## 铁律

### 听众适配

| 听众 | 结构 | 禁忌 |
| --- | --- | --- |
| **纯领导** | 结论先行；给判断不给流程；每段落到"所以对组织意味着什么" | 汇报项目进展、报交付底数、讲工具怎么用 |
| **同侪** | 可以讲方法、手艺、踩坑细节 | 只讲结论不给方法 |
| **跨部门** | 多一层"相邻角色因此少返工"的表达 | 用本部门黑话 |

⚠️ **不要接前一场的话当前提。** 引用别人的分享可以，但必须能独立成立——在场多半有人没听过那场。

### 实例纪律（翻车率最高的一环）

1. **出处必须核实到原文**。AI 生成的多角色评审报告**不是真人发言**——把它说成「测试跟我说」，被追问「哪个测试」就下不来台。真实的说法是「我让 AI 站在测试视角审我的文档，它提出……」；
2. **剥业务专名**。自检：**一个从没用过这个产品的人，听完这句知道在说什么吗？** 卡型代号、版本号、内部字段名一律换成结构描述；
3. **去行话**。不说"空指针"、不说 Given-When-Then、不说"链路"；
4. **每个实例补一句共性后果**。只说"我的话不够精确"是手艺问题，领导不关心；说"过去有人多问一句就澄清了，现在没人问"才是组织问题；
5. **数字要有出处**，且只念听众记得住的那两个。外部研究引用全场不超过两三处，引完立刻回到"我这儿是什么情况"。

### 页面设计：演讲 ≠ 文档

- **每页一个观点**，多了就拆页；
- **每块文字 ≤ 12 字，单页 ≤ 220 字**（结构化排版可放宽，整段文字压到 150 内）；
- **正文最小 14px**（投影等效 ≥20pt），标签可到 12px；
- **中文标题必须用黑体，字重 ≥ 500**。⚠️ 衬线字体栈里若只有西文字体，中文会 fallback 到宋体；宋体横细竖粗，再配 `font-weight: 300`，投到会议室后排横画会直接消失；
- **统一三段式骨架**：眉标 → 大标题 → 一块视觉 → 一句落点。九页节奏一致，听众知道每页看哪儿；
- **讲稿退回讲者稿**。页面上写了讲者要说的话，听众就会低头读，不听你说。

### 语言

- **破折号全场 ≤ 2 处**。中文 AI 味的头号特征，用句号或逗号代替；
- **「不是 A，是 B」不要连着出现**。分散在不相邻的页上，两三处即可，连续四页就腻；
- **不强行升华、不硬凑金句**。收尾收在事实上（一张状态表、一个判断）比收在漂亮话上稳；
- 用户自己写的句子不要擅自"优化"，只补错别字。

## 云文档同步（飞书及同源私有部署）

用 `lark-doc`，或本机自带的私有部署云文档 skill（若有，不随本仓库分发）推送时：

- **必须 `--batch-size 5`**。默认批次会触发频控，导致**推送静默截断**——返回成功信封，但文档只写了一半；
- **推送后必须验证末段存在**（`get-text | grep 最后一节标题`），不要只看返回码；
- **文档标题 API 改不了**，正文推送完要提醒用户手动改；
- **覆盖前先存档评论**：`list_comments` 导出到 `_private/`，正文重建后锚在旧文本上的评论会失效。

## 导出 pptx

两条路，各有取舍，可以都给：

| 方式 | 视觉 | 可编辑 | 何时用 |
| --- | --- | --- | --- |
| **截图版** `scripts/export_pptx.py` | 100% 保真 | 否 | 现场只能用 PowerPoint 放映 |
| **重建版**（python-pptx 逐页手写文本框和形状） | 有偏差，换机器字体会替换 | 是 | 需要临场改字 |

重建版没有脚本，也不该有——每页版式不同，自动转换只会产出四不像。真要可编辑版，
按内容手写，并接受视觉打折。

**现场优先级：HTML 全屏 > 截图 pptx > 可编辑 pptx。**

## 交付前检查

- [ ] 三件套内容一致，措辞对得上
- [ ] `check_deck.py` 四档版面全清
- [ ] 逐页截图人工翻过一遍
- [ ] 每张原话卡与原始记录逐字核对，出处经得起追问
- [ ] 不出现学校 / 学生 / 账号 / 内部链接 / 真实人名
- [ ] 承重页（最硬的那一两页）口播词写死并掐过时间

## 常见错误

| 错误 | 后果 |
| --- | --- |
| 把讲稿铺在页面上 | 听众读页面，不听你说 |
| 实例太垂，需要一线上下文才懂 | 领导听到第三个专名就走神 |
| 只讲"我做了什么"，不讲"所以呢" | 听成工作总结 |
| 因果链断裂（问题跳到方案） | 听成你在多干活 |
| 用衬线字体 + 细字重排中文标题 | 投影后排看不清 |
| 溢出检测只查越界 | 漏掉"内容区撑破"和"压住落点"两类真实重叠 |
| 云文档推送不验证完整性 | 文档写了一半，自己不知道 |
