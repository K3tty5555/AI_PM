# 登录态交接协议（A4 · 公共基础设施，acceptance / 竞品实探 / 权限跑批共用）

> 2026-07-12 落地（Stage4-A4，内研 ≥8 次交接实证）。目的：把"起浏览器→等登录→断线重连→恢复现场"从每次现编，变成一套固定话术与检查步。消费方：ai-pm-acceptance（本目录）、ai-pm-research 登录态实探、未来 `/ai-pm ops` 权限跑批。

## 固定流程（四步，每步有检查）

### 1. 起浏览器（复用既有工具，别现写）
- acceptance 场景：`bash .claude/skills/ai-pm-acceptance/scripts/start-browser.sh`（CDP 端口固定）。
- 其它场景同款模式：真 Chrome + CDP 调试端口；**Playwright 只连不装**（先查本机缓存，禁擅自 install——老铁律）。

### 2. 等登录（人机分工固定话术）
- AI 说："浏览器已起，请完成登录（含扫码/SSO）；登好回一句「好了」。"——**登录动作永远是人的**，AI 不碰凭证。
- 人回复后 AI 先**探活验证**再开工：读当前 URL + 一个登录态才可见的 DOM 锚点（如用户名节点）；取不到=没登成，如实说、别硬跑。

### 3. 断线重连（现场恢复三步）
1. CDP 探活失败 → 先试重连同端口（浏览器可能还活着，只是连接断了）；
2. 重连不上 → 重起浏览器 + 请人重登（同第 2 步话术）；
3. 登录恢复后**回到断点页面再继续**：从台账/trace 里取"最后成功操作的页面 URL + 步骤号"，导航过去核对锚点，再从下一步接着跑——不从头重跑（13 小时验收会话的教训）。

### 4. 收尾
- 只读探索场景（竞品实探）：看完退出登录（只读纪律）。
- 验收/跑批场景：留痕收尾（trace/台账落盘）后关浏览器；下轮重起。

## 检查步速查

| 时机 | 检查 | 不过怎么办 |
|---|---|---|
| 开工前 | CDP 探活 + 登录态 DOM 锚点 | 走第 2 步话术，不带病开工 |
| 每轮操作后 | 当前 URL 记进台账（断点恢复的锚） | — |
| 断线时 | 先重连、再重起、后重登（顺序别反） | 三步都失败→报告卡点，不静默重试 |
