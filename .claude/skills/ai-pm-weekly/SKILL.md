## 角色说明

帮你把散乱的工作记录整理成专业周报，无需提前整理格式，随意描述即可。
如果配置了产品分身（ai-pm-persona），自动应用你的写作风格，让周报更像你写的。

## 执行流程

1. 引导用户描述本周工作，明确告知：可以随意描述，不需要任何格式
2. 如信息不足，追问一次补充：本周有什么亮点/阻碍/风险？下周重点是什么？
3. 自动将内容归类：已完成 / 进行中 / 下周计划 / 风险依赖
4. 检查 `templates/prd-styles/` 是否配置了产品分身风格，有则应用措辞习惯
5. 按选定模板（`--detail` 或 `--brief`）输出周报
6. 保存到输出文件

## 产品分身集成

- 检查 `templates/prd-styles/` 是否有当前生效的风格配置
- 有则参照该风格的措辞习惯（用词、句式、简洁度）生成周报
- 无则使用标准中性专业风格

## 输出格式：团队同步版（`--detail`，默认）

```
# 周报 - {姓名} - {起始日期} ~ {结束日期}

## 本周完成
- {已完成事项，带项目/背景说明}

## 进行中
- {进行中事项} — {当前进度 / 下一步行动}

## 下周计划
- {计划事项}

## 风险与依赖
- {风险项}（如无则省略此节）
```

## 输出格式：向上汇报版（`--brief`）

```
本周重点：{1-2句话核心进展}

完成：
- {条目，每条一行，简洁}
- （3-5条）

进行中：
- {1-2条最重要的}

下周：
- {2-3条最重要的}
```

## 输出文件路径

每个统计周期必须使用独立子目录，禁止把周报文件直接堆在 `output/weekly/` 根目录：

```text
output/weekly/{开始日期}_{结束日期}/
└── 周报.md
```

- 目录日期使用完整 `YYYY-MM-DD_YYYY-MM-DD`，以实际统计窗口为准。
- 同一周期的补充分析、数据表和 HTML 报告统一放入该目录，不另建散落文件。
- 项目级 SOP 规定为每期固定产出的配套文件（包括内部对话记录）必须自动生成，不等待用户重复提醒；同时遵守对应的脱敏、权限和完整性校验规则。
- `output/weekly/` 根目录只保留 `README.md` 和日期子目录。
- 目录不存在时自动创建（`Bash(mkdir)`）。
